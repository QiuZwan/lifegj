## 诚信约定（v1.9 起，v2.0 延续）

这一版把「看起来像真的」全部清掉了。如果你在别处见过相反的说法，以本节为准：

- **不做推算、不编造**。没有记录的地方显示空态，不填假数字。曾经的写死值（`savedTotal = 288`、`closedCount = 3`、写死的「已用 128 天」）已全部删除。
- **统计全部可由列表复算**。已关闭笔数、每月少支出、本月花销、归档文件数，都是由真实列表现算，不是各自维护的独立计数器。
- **首次安装是干净的**。不自动塞演示内容，首页 / 守护 / 档案 / 记账都是真实空态；想看效果需在「我的 → 载入演示数据」显式载入，且演示订阅带「演示」角标，与真实记录区分。
- **扣费记录来自真实来源**。不再按 `nextDate` 倒推伪造「近半年已扣」。扣费流水只有三个来源：短信扫描、通知捕获、你手动补记。
- **不知道就说不知道**。短信 / 通知里没写明扣费日的，不会猜一个日期，而是留空并标「扣费日待补全」。
- **没接 AI 就明说是离线模式**。内置额度和你自己的接口都关掉之后，对话页顶部直接写「离线规则模式」，不会假装还接着大模型。
- **内置额度不冒充「你自己的」**。v2.2 起打包了一份共享免费额度（智谱 GLM-4-Flash），界面上写清它是什么：大家共用、会排队、Key 就在安装包里（只是倒序存放，防的仅仅是扫包脚本，不构成任何保密）。你填了自己的 Key 就自动让位，两块不会偷偷混用。
- **AI 只依据本机快照回答**。提示词里明确要求「快照里没有的直说没有」，不猜数字、不编日期、不编商户；模型给出的动作由本机校验后才落库，非法动作直接丢弃。
- **联网去向写清楚**。只有两处会出网：桌面天气（可关闭）、AI 智能管家（v2.2 起默认开着，用的是内置共享额度，可一键关闭；关掉又没填自己的，就完全离线）。「我的 → 数据与隐私」里如实列出，连「共享 Key 明文在安装包里、额度是所有人共用的」这件事也一起写。

## 数据与链路（本机数据版）

- 全部数据保存在本机 SharedPreferences（`lifebutler` / `state_v1`，JSON），重启、杀进程均保留；卸载即清除。
- 记录入口：今日 / 守护 / 时间线 / 家庭 / 档案各页均有「+」；点任务 / 义务可标记完成，长按可删除或编辑。
- 对话可用：接了 AI 就听整句话（加订阅 / 加家人 / 记日子 / 记账 / 问账）；没接 AI 时退化为规则模式，仍支持「记一下：……」「记账：午饭 25」「今天有什么安排」「今天花了多少」「订阅花了多少」「取消 XX」。
- 联动：关闭订阅 → 守护清单「关闭中」+ 我的统计与省下金额；添加订阅 → 今日「替你盯着的」最近一笔；添加义务 → 时间线倒计时 + 今日计数；导出家庭档案 → 生成文本分享。

## v2.10 新增

### 点一下管家：停在原地，不转了

以前不管你在干什么，那台小机器人一直在自己转。这一版把它改成**可停可走**：

- **点一下它就在原地停下来**，再点一下（收起面板）继续转。停下来是"不再换角度"，
  **位置和大小都不动**——不是把它挪走、也不是把它冻成一张死图，待机时那点轻微"呼吸"缩放还留着。
- 「智能管家」页那台大字号的也统一成同一个规则：**点一下停、再点一下转**
  （原来是"点一下自转一整圈"），页面上的说明文案同步改掉了。
- 顺带修掉一个位置上的坑：面板打开时会加键盘内边距，悬浮层的高度会被键盘压矮一大截
  （实测 1080×2047 → 1080×1227）。位置本来是「归一化分数 × 层高」，拿被压矮的层高去算，
  机器人就会**整体往上跳**、收起面板又跳回来，看起来就像"点一下它就不在原地了"。
  现在位置换算只认**面板收起时**量到的那个高度（`baseArea`），键盘弹起时只做
  「别被键盘挡住」的夹取，不做比例缩放——只要它本来就在键盘上方，就一格都不动。

实现上只用了一个参数：`ButlerSpin(spinning = ...)`。要注意的是这是个**普通参数**，
在它内部那条自转用的 `LaunchedEffect` 里直接读只会拿到"进来那一刻"的值（而且不报错、只是照旧转），
所以协程里读的是 `rememberUpdatedState` 包过的那一份。

### 换应用图标：墨环 · 玉绿四角星

启动器图标从原来的「守 · 穹顶」换成新 logo：**一道墨环围住一颗玉绿四角芒，环在正上方留一道竖缝**。

- 环的外径取 65dp（108dp 画布），落在 Android 保证可见的 66dp 安全圆内，任何遮罩都不会切到环。
- 生成管线（脚本随仓库走，可重跑）：`design/icon/build_icon.py`（量图 → 出三层 XML → 出对照预览），
  `.workbuddy/tools/svg_check.py` 按 SVG 规范把 XML 里的 `A` 圆弧指令解回多边形渲染，用于自证画对了。

## v2.9 新增

### 悬浮小管家：拖到哪儿、点一下就能说话

以前要跟管家说话，得先切到「智能管家」页。这一版把它做成一个 **App 内全局的小机器人**：

- **默认贴在屏幕右侧**，在「今日 / 守护 / 家庭 / 我的」以及各个浮层页面上都在，随时看得见。
- **按住就能拖到屏幕任何地方**（上下左右都行），松手的位置会**记进本机**（`state_v1` 里的 `bfx` / `bfy`，
  存的是**归一化分数**而不是像素——可拖动范围会随设备、系统栏高度变化，存像素下次就可能跑到屏幕外）。
  关掉 App 再打开，它还在你放下的地方。
- **点一下就地说话**：旁边弹出一个小面板，直接打字发给管家，回复显示在机器人上方，不用先跳页面。
  面板里还会如实列出「已写进本机」的内容；管家说要带你去某一页时，面板里会出现「带我去」。
- 面板右上角可收起，底部有「完整对话」直接跳到「智能管家」页。面板里说的话和那一页是**同一份记录**。
- 这个小机器人和「智能管家」页那一台**是同一台**（同一套序列帧），并且**一直在自己慢慢转**，
  一眼就能看出它是活的、能点；拖动中会微微放大一下，表示"被拿起来了"。
- **「智能管家」页里不出现它**——那一页有自己的大机器人，两个一起出现会看花眼，也分不清哪个能拖。

两个实现上的选择：位置只在**松手时**写一次盘（`butlerFx` / `butlerFy` 故意不是 Compose state，
做成 state 会让整棵界面树跟着拖动每帧重组）；键盘内边距只加在这个浮动层上，别处打字不会让它乱跳。

## v2.8 新增

### 管家在模拟器上也能转（不再是一张贴死的图）

真机的 3D（Filament）在模拟器上跑不起来——软件 GPU（SwiftShader）编译不过 Filament 的着色器，
引擎会直接 panic（详见 v2.6 一节）。所以这一版给**没有硬件 GPU 的设备**补了一条路：

- `design/butler3d/render_spin.py`：**纯 CPU 光栅器**（只用 numpy + Pillow），把同一个 glb
  按绕 Y 轴 24 个角度渲染成序列帧，输出到 `app/src/main/assets/butler_spin/`（24 张 WebP，共 0.8 MB）。
  渲染分辨率是成品的 2 倍再缩下去（超采样），边缘不会有锯齿；取景对所有帧用同一个并集包围盒，
  转起来不会"抖"。
- `ui/components/butlerspin.kt` 的 `ButlerSpin`：**空闲时自己慢慢转**（每帧 700ms，24 帧约 17 秒一圈）、
  横向拖动 1:1 跟手转（约 620px 一圈）、点一下自转一整圈；手一碰就停，松手 1.6 秒后接着转。
  取帧走 `conflate()` 而不是 `collectLatest()`——**后者会在快速拖动时把正在解码的那一帧也取消掉，
  结果一帧都显示不出来**。帧是懒解码 + 12 张 LRU（约 11 MB，别再往上加）+ 预取相邻帧。
- ⚠️ **手势挂在最外层的 Box 上，不要挂到 `Image` 上**：`Image` 的布局高度由位图固有尺寸决定、
  不等于这块可视区，手指落在图上方的空白里什么都收不到——实测"在图上拖能转、在图上方的空白拖毫无反应"。
  另外只认 `detectHorizontalDragGestures`，纵向的拖动留给页面滚动。
- 真机那条 Filament 路径也加了**静止自转**（30 秒一圈，转的是节点的 `rotation` 而不是相机，
  免得跟用户自己的拖动抢）。⚠️ **别用 `Animatable` 去驱动这个空闲自转**：它的 `MutatorMutex`
  会把驱动它的那个 `LaunchedEffect` 的 Job 一起取消掉，表现是"拖一下就永久停转"，而且不报错。
- `ButlerScene` 的分支：硬件 GPU → Filament 真 3D；软件渲染 → `ButlerSpin`；两者都失败 → 静态图。

### 底栏图标不再是一团黑

未选中态原来按线性图标的墨色（LbInk3）去压亮度，机器人那张位图有一大块深色面罩，
压完就糊成一团黑。现在只去饱和 + 轻压暗（`RASTER_ICON_INACTIVE_K = 0.72`），读成"灰的机器人"；
取景也从"只有头"改成"头 + 上半身"（`make_assets_from_cut.py` 的 `band=0.62`），24dp 下才认得出。

## v2.6 新增

### 智能管家页是真的 3D 模型（能转的那种）

v2.5 的「全身形象」仍然是一张渲染图，这一版换成了**真正的 glTF 3D 模型**：加载页面即出现，手指拖动可旋转、双指缩放（SceneView 自带轨道相机）。渲染引擎是 Filament（经 SceneView 4.18.0 封装接入 Compose）。

- 模型来源：以 v2.5 的全身形象图为输入，用**腾讯混元图生 3D** 服务生成 GLB（6 万面），原始输出 36.4 MB——体积几乎全在 3 张 4K PNG 贴图上。
- 瘦身：`design/butler3d/shrink_glb.py` 把贴图降到 1024（baseColor 转 JPEG q88，normal / metallicRoughness 保持 PNG），几何一字节不动，压到 **3.2 MB（8.7%）**。最终随包文件：`app/src/main/assets/models/butler3d.glb`。
- 渲染：`ui/components/butlerscene.kt` 的 `ButlerScene`。环境光用球谐常数（`IndirectLight.Builder().irradiance(1, sh)`）而不是 HDR 贴图——零额外体积。
- **软件渲染设备自动回退**：Filament 的 `blitLow` 着色器在 SwiftShader（模拟器的软件 GPU）的 GLSL 编译器上编译不过，引擎会 native panic 直接带走进程。`ButlerScene` 进 Filament 之前用 EGL 读一次 `GL_RENDERER`，名字带 SwiftShader / Software 就直接用 v2.5 的静态图，不崩。真机 GPU 不受影响。
- 依赖：`io.github.sceneview:sceneview:4.18.0`。**只能用 ≤4.18**——4.35+ 要求 compileSdk 37（本项目 35），4.20+ 用 kotlin-stdlib 2.4（本项目 Kotlin 2.2.10 读不了那个 metadata）。
- release 包只保留 `arm64-v8a`（Filament 的 native 库很大，全 ABI 会把包撑爆）；debug 保留全部 ABI 供模拟器用。

## v2.4 新增

### 管家插图换成 3D 版（带真透明通道）

原来是按主题色画的一版矢量插图（`lb_butler_scene.xml` + `values-night` 里一套深色配色）。现在换成 3D 渲染的机器人：骨白陶瓷脑袋、玉绿报童帽、圆框护目镜里亮着玉绿竖瞳，两只机械手扒在一张深玉绿卡片的上沿往外探头。**只有这一张图**，深浅色模式共用——它不是"两套配色"，而是带 alpha 的透明位图，卡片和机器人自己就是完整的一幅画面，放在骨白底和墨绿底上都成立。

- 资源：`res/drawable-xxhdpi/lb_butler3d.webp`（960×800，67 KB，WebP + alpha）。
  放在 `xxhdpi` 而不是项目里其他插图所在的 `drawable-nodpi`，是为了让 Android 在低密度设备上解码时能下采样（nodpi 会一律按原始像素解码，960×800 的 RGBA 是约 3 MB 内存）。宽高比 **1.200**，界面按 `aspectRatio(1.2f)` 摆，改图别改这个比例。
- 源图与预览：`design/butler3d/butler3d_source.png`（ImageGen 原始输出）、`design/butler3d/preview/`（浅色底 + 深色底各一张，用来肉眼验收边缘有没有白边）。
- 生成脚本：`design/butler3d/make_butler3d.py`（和源图放在一起，跟仓库一起走）。**重做插图时用它，不要手工裁图**——里面做了三件事：(1) 抠背景（颜色谓词 + 从画布边缘漫水填充，只把"从边界连通过来的"那片当背景，避免把机器人身上的近白高光啃出洞）；(2) 裁掉右下角的生成水印、并把卡片裁到"自画面下方出画"；(3) 存 WebP 并出两张预览图。
- 在应用里的样子：`design/butler3d/screenshot_app_light.png`（浅色模式）、`design/butler3d/screenshot_app_dark.png`（深色模式）—— 都是模拟器里「智能管家」空态的真实截图，可用来对照深浅色下的边缘有没有残留底色。

### 踩过的坑：`background: transparent` 不生效

ImageGen 传 `background=transparent` 时，模型**不会**给 alpha 通道，而是把"透明"理解成图案、把灰白棋盘格**画进像素里**（实测输出是 RGB 而不是 RGBA，两色只差约 12 个灰阶还带噪点，按颜色抠不干净）。可行的做法是让它画**纯洋红底**（`RGB 255,0,255`——主体里永远不会出现的颜色）再自己按色度抠；但更省事的是先用一张构图满意的图，按上面的脚本把低对比背景整体抠掉。

### 「说了却没做」这件事，加了两道防线

实测里出现过一种很难受的情况：管家回一句「已经帮你加好了」，可本机什么都没有——因为小模型偶尔会只写 `reply`、把 `actions` 交成空数组（`glm-4-flash` 与 `glm-4.5-flash` 都实测到过，约 1/16 的概率；换模型收不干净）。处理办法：

1. 提示词里专门加了一段「reply 说办好了、actions 却是空的，这就是骗人」，并在追问时**把动作格式表一并带上**（`ACTION_CHEATSHEET` 常量，与系统提示词共用同一份，改一处即可）。
2. 识别出「说了做却没给动作」时，**带着它自己刚才那段 JSON 追问一次**，只要它把动作补上。
3. 补过一次仍然没落库，回复后面会挂一句实话：**「（这句我没能写进本机，补上金额或时间再说一次）」**——不替模型圆谎。

另外把「没找到…未改动」和「真写进去了」在代码里区分开了（`Applied.wrote`）：以前模型说「把物业那条标完成」而本机没找到时，那句解释也被算成「办好了」，回复里那句「已经标好了」就没人纠得动。

### 顺带修掉一个老 bug：首次安装的第一次落盘会静默失败

`ButlerStore` 的 `init { load() }` 原本写在类体中间，而 `load()` 里的 `save()` 会用到声明在后面的 `dismissed`。Kotlin 按声明顺序初始化属性，所以首次安装时那次 `save()` 会抛 NPE 被自己的 `catch` 吞掉——**表现是界面上一切正常、`SharedPreferences` 里却一直是空的**，直到用户做了下一次改动才写进去。现在 `init` 挪到类体最后，`save()` 的 catch 也在 debug 包里留了一行日志。

> 这个是靠端到端脚本「读不到基线」暴露出来的：脚本按 `shared_prefs` 读，等了 36 秒、按 HOME 退到后台都还是空文件，而界面上明明有那条欢迎语。

### 内置共享免费额度（装完就能用）

v2.0/v2.1 的 AI 管家要你自己去注册、拿 Key、粘进来，才能听懂整句话。v2.2 把这一步也省了：安装包里内置了**智谱 GLM-4-Flash**（永久免费的模型）的一份共享 Key，装完打开对话页就已经是「已接入」状态，说「加个订阅：网易云 15 块，每月 5 号」它会直接写进守护清单。

**界面上怎么显示**（不装、不骗）：

| 情况 | 对话页顶部 | 「我的 → AI 智能管家」那一行 |
|---|---|---|
| 用内置额度（默认） | AI 已接入 · 内置免费额度 · 智谱 GLM-4-Flash | 内置免费额度 |
| 填了自己的 Key | AI 已接入 · 你的接口 · `模型名` | 你自己的接口 |
| 两个都关 | 离线规则模式 | 未接入（离线规则） |

**优先级**：你自己填的三项（接口地址 + Key + 模型名）齐全时，**一定以你的为准**，内置额度自动让位；没填才用内置的。填了一部分（比如只粘了 Key 没填地址）不会生效，弹窗会提示「要么都填、要么都不填」。

**必须说清楚的风险**（`readme` 与「数据与隐私」页都写了，不藏）：

- 这把 Key 就在安装包里，**一定拿得到**。它只被**倒着存**（`BUILTIN_KEY_REVERSED`，取用时 `.reversed()` 翻回来），好让 `strings app.apk | grep` 这种扫包脚本捞不到明文——反编译看一眼代码、或者把串反过来，立刻就还原了。**这不是安全措施，别当密码用。**
  - 为什么不用「拆成两段再拼」：R8 会把 `A + "." + B` 直接折成一个整串写进 dex。这个版本的第一次构建就撞上了——拆开之后整串照样在包里（已用 dex 自检确认），所以改成了倒序存放。
- 所有装了本应用的人**共用这一把 Key、共用同一份额度**。用的人多了会排队、被限流，甚至被 智谱 封掉。
- 它只连 `open.bigmodel.cn` 这一家，并且**只在用户没填自己的接口时才被使用**。
- 额度用完或被封时，对话页会如实说「这次没连上模型（原因）」，并自动用离线规则兜底，不会假装成功。

**用户能怎么改**：「我的 → AI 智能管家」→ 顶部「内置免费额度」卡片上的按钮一键开启 / 关闭；关掉之后没填自己的 Key，就回到离线规则模式。想换成自己的，把三项填上保存即可。

**开发者怎么换 / 撤这把 Key**（全部在 `data/aibutler.kt`）：

- 换 Key：把 `BUILTIN_KEY_REVERSED` 改成新 Key 的**倒序字符串**（用 Python 一行就能算：`print(key[::-1])`）。
- 换平台或换模型：改 `BUILTIN_BASE` / `BUILTIN_MODEL`；换成非智谱的服务时注意 `AiButler.postJson()` 里用的是 `Authorization: Bearer $key`（智谱与绝大多数 OpenAI 兼容服务都是这个）。
- 撤掉内置额度：把 `AiConfig.useBuiltin()` 的默认值从 `true` 改成 `false`，并把 `BUILTIN_KEY_REVERSED` 置空即可。
- 系统状态页的「AI 智能管家」与「数据与隐私」页会自动跟着显示当前来源，不需要另外改文案（走的是 `AiConfig.source()` / `statusText()`）。

- **怎么做事的**：一次请求把「本机数据快照」和你的话交给模型，模型返回一个 JSON：`{"reply": "要说的话", "actions": [...]}`。`reply` 显示在对话里，`actions` 由本机逐条校验后真正写进 `ButlerStore`——所以「加订阅」「加家人」「记日子」都会立即出现在对应页面，不是只回你一句「好的」。
- **能执行的动作**：`add_task`、`add_expense`、`add_subscription`、`add_charge`、`close_subscription`、`add_obligation`、`add_member`、`add_key_date`、`add_archive`。模型给出未知动作或非法参数（金额 ≤ 0、名字为空）时直接丢弃，不写入。
- **查询**：快照里包含当天日期、待办、进行中订阅（含合计与下次扣费日）、已关闭笔数与每月少支出、到期事务、家人、关键日期、档案组、相册张数、今日 / 本月 / 近 30 天记账明细与分类合计、真实扣费流水。问账、问订阅、问日程都由模型读快照回答，不问一次写一次。
- **执行回执**：这一句真正写进去的东西，会以「已写进本机」的小卡片单独列在对话流里，和模型的客套话分开，方便核对。
- **失败怎么办**：连不上或模型没按格式回 JSON 时，对话页会如实说「这次没连上模型（原因）」，并**自动用离线规则兜底**处理这一句（能记事就记事，能记账就记账），不会静默失败也不会假装成功。
- **隐私**：Key 只写在本机 `SharedPreferences`（`lifebutler_ai`），**不写入备份文本**，界面上只显示掩码。启用后，你说的话与上述快照会发往你自己填的那个地址；除此之外不发给任何第三方。不填接口 = 完全不联网。

## 运行方式

- 环境：Android Studio（Ladybug 及以上）、JDK 17+；`compileSdk = 35`、`minSdk = 26`、`targetSdk = 35`。Gradle 用仓库自带的 wrapper（9.0-milestone-1），无需另装 Gradle。
- 图形界面：用 Android Studio 打开本目录 → 等待 Gradle Sync → 运行 `app` 配置。
- 命令行：

  ```bash
  ./gradlew assembleDebug     # 调试包
  ./gradlew assembleRelease   # 签名发布包（需先补上密钥文件，见下）
  ```

- `local.properties` 指向本机 SDK 路径，**不入库**；换机器时请自行创建并填入自己的路径。

## 修改指南

- 颜色 / 圆角 / 字体阶梯：`ui/theme/theme.kt`（token 与设计稿一一对应）。
- 数据层：字段、派生统计、日期计算与对话回复规则均在 `data/butlerstore.kt`。相册模型是 `ButlerPhoto`（字段 `path` 为绝对路径），与 `ButlerMember.photo`（家人头像）互不相关。
- 备忘录：模型 `ButlerMemo`、分类列表 `memoCategories`、增删改 / 搜索 `searchMemos()` / 排序 `sortedMemos()` / 分类管理都在 `data/butlerstore.kt`；界面在 `ui/screens/ScreensMemo.kt`（含编辑弹窗与提醒时间选择器）。单条提醒的闹钟与通知集中在 `data/reminders.kt` 的 `MemoReminders`（排期 / 取消 / 重排）与 `MemoReceiver`（到点发通知）；收件器已在 `androidmanifest.xml` 声明，开机时随每日简报一起 `rescheduleAll()`。**要改提醒行为，只动这两个对象即可，界面无需改动。**
- AI 管家：`data/aibutler.kt`。上半部分是 `AiConfig`（配置读写 + 掩码 + 内置额度），下半部分是 `AiButler`（`ask()` 一次请求拿 reply + actions、`ping()` 测连接、`systemPrompt()` / `snapshot()` 组装提示词与快照、`applyAction()` 校验并落库、`repairActions()` 追补动作）。**要加一个可执行动作，只需在 `applyAction()` 里加一个 `case`，并在 `ACTION_CHEATSHEET`（动作格式表）里加一行**——那份格式表被系统提示词和「追补」那一轮共用，改一处两边都跟上；另外把新动作写进 `resolveScreen()`（只有跳转类才需要）。配置入口 UI 是 `screenslife.kt / AiManagerDialog`。
- 「说了却没做」的防线（别拆掉）：`applyAction()` 返回 `Applied(what, wrote)`，只有 `wrote=true` 才算办成——「没找到…未改动」这类解释性返回必须以「未改动」结尾，否则会被当成成功，让模型的假承诺躲过校对。`looksLikeClaim()` 判断回复像不像在宣称办好了，是的话就 `repairActions()` 追一次；追完仍没落库，回复后面会挂一句「这句我没能写进本机」。
- AI 的「用哪一套配置」全部走 `AiConfig.source()`：`OWN`（用户自己填的三项齐全）> `BUILTIN`（内置共享额度，默认开）> `NONE`（离线规则模式）。需要发请求的地方一律用 `AiConfig.effBase()/effKey()/effModel()`，**不要直接读 `base()/key()/model()`**，否则会绕过内置额度。内置额度相关的常量（`BUILTIN_BASE / BUILTIN_MODEL / BUILTIN_KEY_REVERSED / BUILTIN_LABEL`）都在这个文件顶部。
- 数据落盘：`ButlerStore` 的 `init { load() }` **必须留在类体的最后**（见文件末尾的注释）。Kotlin 按声明顺序初始化属性，`load()` 里的 `save()` 用到了声明在后面的字段；放到前面执行会抛 NPE 被 `save()` 的 catch 吞掉，现象是「首装后 prefs 一直是空的、界面却正常」，极难查。
- 端到端自测（Windows + 模拟器）：`.workbuddy/tools/e2e_ask.py` 用 `--es ask` 深链逐条发中文、再用 `--es dump` 把本机记录读回来核对真有没有落库（不只看回复文字）。`.workbuddy/tools/prompt_probe.py` 从源码里抽出真实提示词，在宿主机上直接打模型、秒级看它回了什么（改提示词的迭代用这个，别每次重装 App）。`.workbuddy/tools/model_ab.py` 横向比几个模型「会不会老实发动作」。**读本机记录不要退回去读 `shared_prefs`**：那是异步落盘，会读到旧内容。
- 要看界面实机长什么样：`.workbuddy/tools/grab_shot.py --open-tab 智能管家 --out x.png`。它用 `open_tab` 深链直达目标页（**全程不发输入事件**），并在启动后高频截图、按画面特征自动挑出目标页那一帧。为什么这么绕：这台模拟器没有硬件加速，应用渲染首帧要 40~60 秒，之后系统会因为「5 秒内没响应焦点事件」把它 ANR 强杀 —— 所以**不能用 `input tap` 导航**（点本身就触发输入超时）。判定「还在启动图」的判据是**纯黑像素占比**（启动图 0.94 / 应用深色页 0.001），不要用「底部导航栏有没有内容」，系统手势白条会被误判。`.workbuddy/tools/shot_screen.py` 是按文字点控件的旧方案，`uiautomator dump` 在这种机器上经常直接失败，仅供备用。
- 打包产物自证：`.workbuddy/tools/verify_apk.py`。**不要用文件大小判断包有没有更新**（历史上两个内容不同的 APK 字节数完全一样过）。它按内容查三件事：资源按 **SHA-1 哈希**比对（release 会被 `optimizeReleaseResources` 改名成 `res/3t.webp` 这种短名，按文件名找不到）、`classes*.dex` 里应有/不应有的字符串、`output-metadata.json` 的版本号。发布到 GitHub 的包建议再核一次哈希，见 `.workbuddy/tools/gh_release.py`。
- 扫描逻辑（短信 / 通知关键词、商户提取、扣费日期解析、应用白名单、线索池）：`data/subscanner.kt`；通知监听服务：`data/notiflistenerservice.kt`；对应权限与 `<queries>`、服务声明在 `androidmanifest.xml`。
- 档案文件：存于 `filesDir`，对外只读授权走 `res/xml/file_paths.xml` + `androidmanifest.xml` 里的 FileProvider（authority 为 `${applicationId}.fileprovider`）。
- 本机图片：`decodeLocal(path, maxDim)` 按需下采样解码；`LocalImage` / `LocalPhoto` 是唯一渲染入口，传 `maxDim` 控制缩略图内存。新增图片位要记得传 `maxDim`。
- 图标：`ui/icons/LbIcons.kt`（Tabler 路径内联；增改图标直接编辑 pathData）。
- 「智能管家」页 v2.6 起是**真 3D 模型**（软件渲染设备走 `ButlerSpin` 的 24 帧序列，见 v2.8）：`app/src/main/assets/models/butler3d.glb`（v2.7 新机器人，3.4 MB），由 `ui/components/butlerscene.kt` 的 `ButlerScene` 加载（SceneView + Filament，可拖动旋转/缩放），软件渲染设备改走 `ui/components/butlerspin.kt` 的 `ButlerSpin`（预先 CPU 渲染的 24 帧角度序列，`render_spin.py` 生成、存在 `assets/butler_spin/`，空闲自转 + 拖动转圈 + 点一下一整圈；**手势要挂外层 Box，别挂 `Image`**），静态图 `res/drawable-xxhdpi/lb_butler3d.webp`（563×972，同一台机器人）只在序列帧解不出来时兜底。**重做整套形象的顺序**（脚本都在 `design/butler3d/`）：`split_views.py` 拆四视图 → `cutout_neutral.py` 抠图（按行估计背景色；**别改成"与相邻像素比"**，会顺着抗锯齿爬进机身）→ 图生 3D 出 GLB → `shrink_glb.py` 瘦身（**它会重写 bufferView：每张图要带 `buffer: 0`、`buffers[0].byteLength` 要等于新 BIN 长度——漏一个 Filament 就报 "Unable to parse glTF file"**）→ `make_assets_from_cut.py` 出页面图与底栏图标。底部 tab 图标是 `res/drawable-xxhdpi/lb_nav_butler.webp`（头+上半身取景，未选中态用 `inkTone()` 去饱和轻压暗——**别按 LbInk3 压，会糊成一团黑**）。
- 演示数据：「我的 → 载入演示数据」触发，实现在 `ButlerStore.loadDemo()`；演示订阅的来源字段标为「演示」，界面显示角标。**不要把演示数据写进 `load()`**，首启必须为空。
- 图片：`res/drawable-nodpi/` 下的 jpg。当前被代码引用的只有这 9 张：`hero_morning / archive_papers / family_home / review_journal / vault_shelf / avatar_mom / avatar_dad / avatar_user / avatar_cat`；同目录下的 `focus_desk / chat_faucet / family_tea / guard_wallet` 暂未被引用（早期版式留下的素材，删掉不影响构建）。**例外**：「智能管家」的静态回退图在 `res/drawable-xxhdpi/lb_butler3d.webp`（带 alpha，深浅色共用）、底栏图标 `lb_nav_butler.webp` 同目录，不在这个目录——它们需要按密度下采样，放进 nodpi 会一律按原始像素解码。
- 应用名：`androidmanifest.xml` 中 `android:label`；版本号在 `app/build.gradle.kts`（`versionCode` / `versionName`）与 `screenslife.kt` 页脚文案两处，改的时候别只改一处。
- 启动图标：自适应图标 `res/drawable/ic_launcher_background.xml / ic_launcher_foreground.xml / ic_launcher_mono.xml` + `res/mipmap-anydpi-v26/`。
- 签名与发布：`keystore.properties` + `keystore/*.jks` 为**自用密钥，不入库**。本地补齐这两个文件后 `assembleRelease` 才会输出已签名包；缺失时 `assembleRelease` 会产出未签名包（`build.gradle.kts` 里对签名配置做了存在性判断）。
- ⚠️ **源码文件名几乎全是小写**，连清单都是 `app/src/main/androidmanifest.xml`（不是 `AndroidManifest.xml`）。只有 `ui/screens/ScreensMemo.kt` 与 `ui/icons/LbIcons.kt` 是首字母大写。
  Windows 大小写不敏感，所以本机怎么都能构建；但推到 Linux / CI 会因为找不到清单直接失败。**往 CI 上放之前必须先统一改名。** 本文档里的路径已按真实文件名写全小写。

## 本地构建的两个坑（Windows + 本仓库）

1. **Gradle 目录被 IDE 锁住**：Android Studio 开着时，`~/.gradle/caches` 里的 `modules-2.lock`、`transforms/*/results.bin` 会被占用，直接跑命令行构建会 `AccessDeniedException`。绕法是给命令行一套独立的 Gradle 目录，同时把官方 cache 以**只读**方式挂进来（只读不抢锁）：
   ```bash
   # 注意:GRADLE_RO_DEP_CACHE 必须写成 Windows 风格的绝对路径(C:/Users/...)。
   # 写 $HOME/.gradle/caches 会被 Git Bash/MSYS 转成 C:\c\Users\...，Gradle 只会
   # 轻描淡写地报一句 "read-only dependency cache is disabled"，然后在 --offline 下
   # 报 AGP 插件解析失败 —— 看起来像网络问题，其实是路径问题。
   GRADLE_USER_HOME=<repo>/.gradlehome \
   GRADLE_RO_DEP_CACHE=C:/Users/<你>/.gradle/caches \
   ./gradlew assembleDebug --max-workers=1
   ```
   另外 `./gradlew` 自己会联网校验发行版（`validateDistributionUrl`），在会拦 TLS 的环境里会以 `PKIX path building failed` 失败。这时直接调本地已解压好的启动器即可：`~/.gradle/wrapper/dists/gradle-<版本>-bin/<hash>/gradle-<版本>/bin/gradle`。
2. **并发 dex 偶发权限报错**：`mergeExtDexRelease` 在多 worker 下偶发 `AccessDeniedException`。加 `--max-workers=1`，并把 debug / release 分成两条命令分别跑，即可稳定通过。

- 空态与失败态：各页首启即为真实空态（无假数据）；加载 / 失败态只用于**真实需要联网**的功能（桌面天气、AI 管家），取不到就如实说明并（AI 场景下）退回离线规则，不显示编造的错误或成功的假回执。
- 权限说明：`READ_SMS` 仅用于「一键扫描」的本机短信分析，可拒绝；「通知使用权」可选开启（仅本机捕获扣费类通知）；Android 13+ 通知权限用于每日简报以及你自己设的备忘提醒；`INTERNET` 用于两件事——可选的桌面天气（只下载、不上传），以及 AI 智能管家（v2.2 起默认开着，用的是内置共享额度；可在「AI 智能管家」里一键关闭或换成自己的 Key，关掉且不填自己的就完全不联网）；「大致位置」只给天气用。均可随时在系统设置撤销，不影响其他功能。
- 未包含：云端同步、后台推送服务、账号体系。数据仅保存在本机，卸载即清除。
- 适配：手机竖屏为主（主界面已锁定竖屏）、内容可滚动；系统栏 edge-to-edge 沉浸式适配；深色模式已覆盖全部界面；平板适配未做。

## 已知限制

- 第三方订阅无法由本应用代取消，本应用只提供步骤与提醒；对 AI 同样如此，它会如实说做不到并帮你记成待办。
- 「通知使用权」只能捕获开启之后到达的通知，开启前的历史通知无法回溯。
- 档案文件单份上限 4 MB（照片会自动压缩，通常不受影响）；相册单张压到最长边 1600。
- `READ_SMS` 属 Google Play 受限权限，本工程定位为自用 / 侧载，未针对上架做合规改造。
- AI 管家默认用打包在安装包里的智谱 GLM-4-Flash 共享免费额度（Key 就在包里、所有人共用、可能排队或被限流，详见「v2.2 新增」；可一键关闭或换成自己的接口）。小模型偶尔会**只写回答、不发动作**，甚至不按 JSON 回答——这时本应用不会擅自写入，会先追问一次把动作补上，仍补不上就在回复里如实写明「这句我没能写进本机」，不替模型圆谎。
- debug 包里有两条只对调试版生效的深链：`--es ask <句子>`（替用户发一句话）、`--es dump <nonce>`（把当前本机记录打进 logcat）。这是端到端自动测试用的；release 包的 `debuggable` 为 false，这两条路径永远不会执行，用户装到的包里没有这些入口。
