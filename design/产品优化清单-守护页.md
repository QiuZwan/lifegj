# 生活管家 · 守护页优化方案（基于 v2.17 代码现状）

> **v2.18 已落地**：D3 取消路径前置、D4 详情页删除入口、D5 口径统一（`active` 单一口径）、
> D8 空态三分法、D10 已处理分组、B4 装饰 chip → 扫描入口、A5 副标题写全四处来源、
> C2 新增「上次扫描时间」。
> 另外把「扫描」这一条路从 *「你自己打开那页、我帮你抄」* 升级成
> *「**我替你点进去**」* —— 见第六、七节。剩余待办仍见第四节批次表。

范围：底栏第二格「**守护**」——`GuardScreen`（守护页）、`SubscriptionDetailScreen`（订阅详情）、
`CancelGuide`（取消引导）三块，以及它们依赖的 store 派生量。
依据全部来自**读代码**（`app/src/main/java/com/lifebutler/app/ui/screens/screensguard.kt`，
下文简写 `guard:N`；`data/butlerstore.kt` 简写 `store:N`）。**本轮未做设备实测**，
凡属"按机制推断"的都单独标出来了。

## 一、当前问题

### 1. 交互流程

| # | 问题 | 代码依据 |
| --- | --- | --- |
| A1 | **首屏没有"收口"**：一屏里平铺 7 个区块（线索卡 → 深色合计卡 → 扫描入口 → 提醒条 → 订阅清单 → 关闭统计卡 → 义务卡）。用户来守护页的真实意图只有三个（*接下来要付多少* / *有没有我不认识的* / *哪笔没关干净*），但没有任何一处替他收口，全靠自己往下滚。 | `guard:100-418` 整段是同一个 `Column` 顺序铺开 |

| A3 | **关键操作埋在二级页最底部，危险操作反而在一级页**。想取消一笔：列表 → 点行 → 滚到详情页最底 → 才看到取消引导（概要卡、提醒卡、下次扣费卡、扣费记录、补记按钮之后）。而"删除"是列表行的**隐式长按**。轻重完全倒置。 | 取消引导在 `guard:756-772`；长按删除在 `guard:363` |

## 二、改进方向

### D1 · 首屏收口：把 HeroCard 从"金额牌"改成"结论牌"

- 大数字改成 **「下个月要扣 ¥X」**（口径：`subsDueInMonth` 的下一个自然月，或"本自然月剩余未扣"），
  副标题一行给 **「本月已扣 ¥Y · 在用 N 笔」**（口径统一到 `active`，见 D5）。
- 右上角把装饰性的「M 月」换成**结论 chip**：「2 笔要处理」/「都处理完了」——
  点它滚到 D2 的待处理区。**这是全页唯一需要"收口"的地方。**
  → 直接删掉 `guard:211` 那个 chip。

### D2 · 线索改成"逐条推进"，并把永久性说清楚

- 一次只显示**当前这一条**（卡片式，一行一条），底部「还有 N 条」；点「认得 / 不是我的」后
  **自动推进到下一条**，用户只需连点 N 次、不用滚动、不用等列表重排。
  → 替换 `guard:170-177` 那句"认掉前面几条就会露出来"。
- 「不是我的」文案改成 **「以后别再提」**，下面补一句「（这个商户以后不会再自动加进来）」；
  处理完给 **Undo**（`dismissed` 是列表，撤销就是把它移出去，零成本）。
  → 在 `store` 加一个 `undismissName()`，并在「我的 → 设置」加一个"**不再提示的商户**"管理入口。
- 线索行把 **`pkg` 用起来**：显示成"来自 支付宝 / 微信 / 短信"，替代写死的「来自通知」。

### D3 · 取消路径前置（本次最高收益的一条）

- **列表行右侧直接给一个「关闭」小按钮**（只在非 `closing` 时出现），点它**直接进取消引导**，
  不经过详情页顶部的长滚动。
- **详情页把 `CancelGuide` 从最底移到概要卡正下方（第 2 屏）**。进详情页的人十有八九是为了关它，
  而现在是"概要 → 提醒 → 下次扣费 → 扣费记录 → 补记"之后才轮到。
- 引导里的两个按钮**降级区分**：「复制关闭步骤」改成文字链接；「我已关闭，帮我复核」保持主按钮，
  并把文案改成带承诺的 **「我去关掉了，帮我盯着下一次」**，下面补一句闭环承诺（见 D10）。

### D4 · 详情页补一个**明确的**删除入口

页面底部新增「危险区」一行：**「不再守护这一笔」** → 复用现有确认框（`guard:448-463` 那段逻辑）。
列表长按**保留**作为快捷方式，但不再是唯一通路。

### D5 · 口径统一（P0，这是"算得出来"的错）

**全页只用一个 `active` 口径**（= 非关闭中）：

- `guard:291` 的「N 笔」→ `active.size`；
- `guard:203-204` 的「N 笔订阅」→ `active.size`；
- `guard:306` 的列表**只渲染 `active`**；关闭中的订阅移出清单，进 D10 的「已处理」折叠区。
- 订单统计卡（`guard:369-388`）两个数字统一到**同一基数**：
  要么都用当前关闭中（`monthlySaved` + `subs.count{closing}`），
  要么都改成"累计已关 N 笔 · 累计省 ¥X"。**推荐后者**，因为它更符合用户对"我关掉过多少"的直觉。

### D6 · 补齐钱的口径

深色卡按 D1 改成"下月要扣 + 本月已扣"。数据现成：`subsDueInMonth()`（`store:1556`）
与 `savedThisMonth`（`store:346`），只是从没在守护页用过。

### D7 · 新增「数据从哪来」状态条（把 C1/C2/C3 一次收掉）

守护页顶部（标题下、HeroCard 上）放一条**细状态条**，四路来源各一个小圆点：

```
● 短信 已开   ● 通知 已开   ○ 代扣页 未开   ● 已安装应用
上次扫描：9 月 24 日 14:20                              [重扫]
```

- 点某个圆点 → 直达对应权限页；
- 通知/无障碍服务 **`connected == false`** 时那颗点变 rust 色，文案「被系统断开了」，点一下重开；
- 全部未开时整条换成 amber，一句话：「还没开启任何来源，所以这里可能一直是空的」。

⚠️ `lastScan` 需要**新增标量字段**（按项目约定：只加 `save` 的 `put` + `load` 的 `opt`，不动集合六处）。

### D8 · 空态改成"三分法"

订阅清单空态（`guard:297-304`）要能区分三种情况，各自给一个动作：

| 情况 | 文案 | 动作 |
| --- | --- | --- |
| **没授权** | 「没开任何读取权限，所以我还看不到你的订阅」 | 「去开启」→ 权限页 |
| **没扫过** | 「还没扫描过。我可以从短信、通知、代扣协议清单里帮你找」 | **主按钮「一键扫描」** |
| **扫过但没有** | 「9 月 24 日扫过，四处来源都没找到 —— 也可能是这几家不在覆盖范围（苹果订阅 / 厂商应用商店 / 运营商话费代扣）」 | 「怎么自查」→ 帮助页 |

同时把「点右上角 +」降为次要说明 —— 现在空态**只**说这一句。

### D9 · chip 瘦身

- 一行**最多 2 个** chip：只留**最重要的一个状态**（关闭后仍扣费 > 关闭中 > 明天扣 > 待补全）。
- 「来源」从 chip 改成名称下方的解释性小字，并**带上来源解释**：
  如「来自 代扣页 · 支付宝（你在那一页签的协议）」。这样 v2.17 新加的"代扣页"三个字才有意义。
- 日期列统一成**一种**格式：优先相对（今/明天/N 天后），超过 7 天才用「M-D」，并左对齐与金额分开。

### D10 · 「关闭中」闭环 + 已处理分组

- 文案补上闭环：详情页写清 **「过了 10 月 23 日这个扣费日、且之后没有新的扣费记录，就算停干净了」**，
  守护页的「关闭中」分组顶部也给同一句话。
- 清单只放**在用**订阅；「关闭中 + 已关闭」合并成一条**可折叠**的「已处理（N）」区，
  ↓ 现在它们混在用清单里（`guard:306`），却又不计进合计，是 B1 的根源。

### D11 · 待补全内联补全

金额/日期缺失时，**在那一行或概要卡上直接给「补全」**，只弹缺的那个字段（复用 `LbField(...)` 单字段弹窗，
像 `guard:811-831` 的试用截止日那样），不要每次都进全字段「编辑」。

### D12 · 危险操作分级

定一条全 App 一致的规则：

- **可逆的**（标记关闭、以后别再提）→ 立即生效 + **Undo**，不弹确认框；
- **不可逆的**（删除订阅、删除扣费记录）→ 确认框。

现在正好反了（C5）。同时 Toast 一律换成**页面内留痕的提示条**（可带一个动作按钮）。

## 三、预期体验目标（可验收）

1. **首屏 1 屏内**能回答"下月要扣多少、有几笔要处理"—— 不需要滚动。
2. **「想取消一笔」≤ 2 次点击**（列表行「关闭」→ 取消引导），且**不需要任何长滚动**。
3. **金额口径全页唯一**：合计金额 = 清单条数 × 各行金额，用户能自己加得对（当前 B1 会把这条否掉）。
4. **每个空态都能当场说明原因**（没授权 / 没扫过 / 扫过没有），并各带一个一键动作；不再有"我不知道为什么是空的"。
5. **服务被系统断开**在守护页 1 屏内可见（点一下能重开），不再需要去扫描页才能发现。
6. **一行最多 2 个 chip**，在 **2.0× 大字号**下不折行（沿用底栏 `lbNavLabelSize()` 那套"封顶 + 锁一行"的思路）。
7. 从"我要删掉这一笔"到删掉，**有明确入口、有确认框**，不依赖发现长按。
8. 线索处理从 **⌈N/3⌉ 轮点按 + 等待重排** 降到 **N 次连续点按**（不滚动、不等待）。

## 七、「扫描」这条线：从"你打开我抄"到"我替你点进去"

这是本轮的重点，也是少帅点名的需求。

### 7.1 为什么一定是这两家

国内 App 自己没有支付牌照，**自动续费必然签在某个"收单方"身上**：支付宝 / 微信（绝大多数）、
苹果 App Store、手机厂商商店、运营商话费代扣、部分银行。

所以「爱奇艺的续费」并不是一个独立对象 —— 它在支付宝的「免密支付 / 自动扣款」里，
或微信的「扣费服务（自动续费）」里。**把这两页读全，就覆盖了绝大多数 App。**
剩下那三类（苹果 / 厂商商店 / 话费）无障碍也进不去，只能如实告诉用户自己去看。

### 7.2 四路来源与各自的能力边界

| 来源 | 需授权 | 能拿到的 | 拿不到的 |
| --- | --- | --- | --- |
| 扣费短信 | `READ_SMS` | 近一年扣费/签约短信 → **唯一能"翻历史"的一路** | 关掉短信通知的银行/平台；删掉的短信 |
| 通知使用权 | `NotificationListenerService` | 从**开启那一刻**起的扣费/签约通知；开启时还留在通知栏的也读一遍 | 开启之前的（Android 不给回查） |
| 代扣协议清单 | 无障碍（`AccessibilityService`） | 支付宝/微信那两页上的**协议本身** —— 最接近「我到底在续什么」 | 苹果订阅、厂商商店、话费代扣 |
| 已安装应用 | 无 | 只说明"装了哪些 App" | 不代表开了会员 |

### 7.3 新增：无障碍自动导航（`data/a11ynav.kt`）

v2.17 只做到「你把那页打开，我把页面内容抄下来」。v2.18 起：

```
点「帮我翻进去并读取」
   → 启动支付宝/微信
   → 按 route 逐级点：支付宝 我的 → 设置 → 支付设置 → 免密支付/自动扣款
                      微信   我 → 服务 → 钱包 → 支付设置 → 自动续费
   → 每到达一个窗口，先问「这是不是清单页了？」（looksLikeListPage）
       是 → **立刻停手**，不点任何东西，把窗口交给原来那套解析器
       否 → 精确找下一级入口并点击；找不到就向下滚（每级最多 3 次）
   → 解析出 N 条 → 留痕「读到了 N 条签约」
```

### 7.4 安全底线（这些是**硬性**的，不是"尽量"）

| 规则 | 实现 |
| --- | --- |
| **只点精确相等的词** | `findExact`：去空白后 `text` 或 `contentDescription` 与候选词**完全相等**才命中。**绝不做 `contains`** —— 中文里「支付设置」和「支付」是两回事，包含匹配会点到「支付」 |
| **动作词二次拦截** | 命中后还要过 `FORBIDDEN` 正则（关闭/解约/取消/终止/删除/移除/立即/确认/开通/签约/同意/授权/转账/提现/退出/解除/撤销/修改/编辑/解绑/绑定/付款/续期/扣款$）才允许点。⚠️ **故意不含「支付」**，否则会误伤导航行「支付设置」「免密支付/自动扣款»」 |
| **到位即停** | 认出清单页 → 立即停手，只读不点。清单行上一般就挂着「关闭服务」这类危险字，多点是灾难 |
| **找不到就停** | 每级最多向下滚 3 次；还不出来就 `finish(false, "在「X」这一步没找到入口…")`，如实告诉用户停在哪一步 |
| **总超时 75 秒** | `deadline` + watchdog，超时收手 |
| **只在自己写死的包名里动作** | 无障碍配置的 `packageNames` 锁死支付宝/微信两个包；服务里还用 `pkg != payer.pkg → return false` 再挡一次 |
| **不看输入框、不上传** | 沿用 v2.17 的隐私底线：字符串只在界面上给你看，一条都不上传 |
| **失败是正常结局之一** | 界面永远把手动路径摆在旁边（每张卡都写着「路径：…」+「自己打开」），并明说：**这条路径是照公开资料写的、没在真机上核过** |

### 7.5 诚实边界（必须让用户看见）

- 手上**没有**可用的真支付宝 / 微信账号，所以 `route` 里那几级是**照公开资料写的，没有在真机上核过**。
  这句话已经写进：`PAYERS.route` 的 KDoc、扫描页每张卡下面的小字、以及本节。
- 导航失败不会"假装成功"：`Applied(what, wrote)` 那套防线沿用 —— 没读到就如实挂「翻到了那一页，
  但一条都没认出来（可能这家改版了）」，而不是显示一个好看的 0。
- 代扣页读到的条目**只说明"协议签了"，不写扣费流水**（签约不等于扣过钱），也不自动进守护清单，
  要用户自己点「加入」。
- ⚠️ 权限说明页（`lb_strings.xml`）也同步改了：现在明确写着**它也会替你点导航**、会点哪几级、
  哪些词一律拒绝点击、最长 75 秒。**权限是用户给的，就不能让他到用的时候才知道它能点东西。**
